An API key is a long secret string that lets another tool act on your affiliate program without logging in as you. If you're building a custom integration, connecting an automation platform, or asking a developer to send sales data to Referly from your own system, this is what they'll need.

To find your keys, open **Settings** from the left sidebar, go to **Advanced**, then select **API Keys**. The screen lists every key you've created for the program you're currently in, and has a **Generate New Key** button at the bottom right.

![api-keys-screen](https://qnthgdfusotvjgaxpfie.supabase.co/storage/v1/object/public/public-assets/docs/uploads/1784771609180-597381-final-api-keys-screen-1784771608926.png)

<Info>
  API access is part of the **Business**, **Enterprise**, **Agency**, **Agency Pro**, and **Agency Scale** plans. It isn't included during a free trial of the Business plan: it unlocks when you start your paid plan. On other plans the **Generate New Key** button is locked and selecting it opens an upgrade prompt. See [API access](/help-center/billing/api-access) and [plans and features](/help-center/billing/plans-and-features).
</Info>

## What a key gives access to

Choose **Full access**, **Read only**, or **Custom permissions** when creating a key. Custom permissions let you select read and write access separately for resources such as sales, commissions, analytics and webhooks. Write access does not automatically include read access. Existing keys keep their permissions.

Give each integration the permissions it needs. See the [permission reference](/developer-documentation/api/authentication#resource-permissions) for the complete list.

## Generate a key

Select **Generate New Key** at the bottom right. Choose a permission preset, or select at least one permission under **Custom permissions**. Optionally set a future expiry date and time in your local time zone, then generate the key. The list shows its permissions and expiry status.

A key without an expiry stays valid until deleted or revoked. An expired key stops authorizing requests, so replace it in the integration before its expiry.

![The API Keys page with a newly generated key, its creation date, the Copy button and the Generate New Key button](/images/help-center/settings/generate-key.png)

You can create as many keys as you like. It's worth creating a separate one for each tool or integration, so that if you ever need to turn one off you don't break everything else at the same time.

<Check>
  When the "API key created successfully" message appears, the key is live and ready to use.
</Check>

## Copy your key

Select **Copy** on the key's card to put it on your clipboard, then paste it wherever it's needed — usually a field labelled "API key" or "token" in the other tool.

Unlike some services, Referly keeps your key visible on this screen, so you can come back and copy it again later. That also means anyone who can open your dashboard can read it.

<Warning>
  Keep your key on a server or in a password manager. Never put it in a public repository, a browser script, a support ticket, or anywhere your website visitors could see it. Anyone with the key can use the permissions you granted it.
</Warning>

## Each key belongs to one program

A key defaults to the affiliate program it was created in. For existing programs, switch to each one and generate its own key. If an integration creates a new program through the API, that exact key can also select the new program on operational endpoints. See [program selection](/developer-documentation/api/authentication#select-a-program).

The same applies the other way round: deleting a program's key has no effect on your other programs.

<Note>
  Keys created automatically when you connect [Zapier](/help-center/integrations/zapier) or [Make](/help-center/integrations/make) are managed by those connections and don't appear in this list. Disconnect the app from its own settings screen rather than looking for its key here.
</Note>

## Hand the key to a developer or tool

Requests go to `https://www.referly.so/api/v1`, and the key travels with every request as a bearer token:

```bash
curl https://www.referly.so/api/v1/affiliates \
  -H "Authorization: Bearer YOUR_API_KEY"
```

That's usually all a developer needs from you. The full list of what can be read and written is in the [API reference](/api-reference/introduction), and there's a longer walkthrough in [authentication](/api-reference/authentication).

## Know the request limits

To keep things fast for everyone, each key can only make so many requests in a given period. The limits apply per key and per type of request:

| Type of request | Limit |
| --- | --- |
| Reading data | 100 per minute |
| Creating, updating, or deleting | 30 per minute |
| Anything to do with sales | 20 per 15 minutes |

Going over a limit doesn't disable your key. The request is refused with a "too many requests" response and a note of how long to wait, and normal requests resume once the period is over. If you're importing a lot of history at once, spread it out or use the [import tools](/help-center/manage/customers/import) instead.

## Delete a key

Select the red trash icon on a key's card. The key is removed immediately — there's no confirmation step and no way to restore it.

![delete-key](https://qnthgdfusotvjgaxpfie.supabase.co/storage/v1/object/public/public-assets/docs/uploads/1784771606131-445458-final-delete-key-1784771606042.png)

<Warning>
  Any integration still using that key stops working the moment you delete it, and starts getting rejected as unauthorised. Before deleting a key, check which tool is using it and give that tool a new key first.
</Warning>

Delete a key whenever it may have been exposed — a developer leaves, a key ends up in a shared document, or you stop using a tool. Generate a replacement, update the tool, then delete the old one.
