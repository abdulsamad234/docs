---
title: "Authentication"
description: "Authorize requests with a scoped API key and select the program for operational endpoints."
---

Create a key in **Settings → Advanced → API Keys → Generate New Key**. Choose **Full access**, **Read only**, or **Custom permissions**, optionally set an expiry, then generate and copy the key.

```bash
curl https://www.referly.so/api/v1/programs \
  -H "Authorization: Bearer $REFERLY_API_KEY"
```

Each endpoint lists its required scope. Read and write permissions are independent; full access uses `*`. Existing keys retain their access. Expired, revoked and deleted keys are rejected. Account and agency API access restrictions still apply.

Requests default to the key's original program. Operational endpoints accept `X-Program-Id` for a program provisioned by that exact key. This does not grant account-wide access. Legacy affiliate, referral, sale, link, coupon and promotional-code endpoints continue to use their usual program key.

See [authentication and permissions](/developer-documentation/api/authentication) for all scopes, expiry, program selection and rotation, and [common API rules](/developer-documentation/api/overview) for pagination, retries and errors.

<Warning>
Keep API keys on your server. Do not put them in frontend code, public repositories or query strings.
</Warning>
